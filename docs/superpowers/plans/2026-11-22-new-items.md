# Nowe itemy i moduły 2U: plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 10 nowych itemów (Null pad, Zip tie, Slingshot, UPS, Hotkey v1/v2, Compiler, Bitshift, Overclock, Exploit v1/v2, Snapshot) i rozmiar modułu 2U (UPS, Compiler, Overclock, Bridge v2).

**Architecture:** logika w `src/roguelike.ts` (definicje `ITEMS`, rack, rachunek `scoreMatrix`, koniec matrycy `finishMatrix` / `daemonsAfterMatrix`, reset pokoju w `nextSection`), plansza w `src/matrix.ts` (`dealBoard`, `placeCells`, `TOOLS`), UI w `src/ui.ts` (sklep, rack, narzędzia, skrypt, `newMatrix`). Każdy item idzie wzorcem najbliższego istniejącego: pasywne jak Thumb drive (linia `gear` na rachunku), narzędzie jak Split, komórki jak Data node.

**Tech Stack:** TypeScript + Vite, testy Vitest.

**Spec:** `docs/superpowers/specs/2026-11-22-new-items-design.md`

## Review Focus

1. Hotkey nie może „wpiec” bonusu w zapisany poziom: patch.zip po Hotkey podnosi poziom bazowy o 1, nie o 1 + bonus (test w Task 4).
2. Sprzedaż Hotkey usuwa bonus; Compiler po sprzedaży zostawia zdobyte poziomy (test w Task 4).
3. Upgrade 1U → 2U (Bridge → Bridge v2) przy pełnym racku jest blokowany, a 2U → kupno przy 1 wolnym slocie też (test w Task 1).
4. Exploit nie płaci dwa razy za tę samą komórkę: Loopback na komórkę `$` albo restart matrycy nie daje drugiego $ (test w Task 6).
5. Snapshot nie działa po ostatniej matrycy pokoju ani po wcześniejszym wyjściu; drugi raz w tym samym pokoju też nie (test w Task 7).
